# Guardian Botanical Care（gbc_flutter）详细项目报告

## 1. 项目概述
- 名称：Guardian Botanical Care（gbc_flutter）
- 目的：为用户提供植物识别、养护管理、诊断建议与养护提醒的跨平台应用，支持移动端与桌面（特别是 Windows）。
- 版本：0.7.21+1（pubspec.yaml）
- 许可证：GPL（main.dart 文件头部声明）

## 2. 关键功能（现状推断）
- 我的植物：本地管理用户添加的植物条目（图片、备注、养护记录）。
- 养护提醒：基于时间/位置/天气和用户设置生成提醒（推断依赖：geolocator、permission_handler、天气/位置服务）。
- 拍照识别：通过相机或相册拍照并发送到识别 API 获取植物种类或疾病判断（image_picker、http/dio）。
- 专业诊断：上传图片/数据获取更详细的诊断或养护建议（可能有独立诊断 API）。
- 会员系统：包含会员页面（MembershipScreen），可能用于解锁高级功能或云同步。
- 设置与主题：多主题支持（AppThemes）、动态/玻璃风格底栏等；支持中英两种语言（zh-CN, en-US）。
- 启动页与桌面优化：flutter_native_splash 配置、Windows 窗口管理与图标设置、SQLite FFI 在桌面上运行。

## 3. 架构与关键文件映射
- lib/main.dart：应用入口，路由、提供者（PlantProvider, SettingsProvider）、窗口/FFI 初始化逻辑。
- lib/screens/：UI 页面集合（MyPlantsScreen, CareReminderScreen, PhotoIdentifyScreen, DiagnosisScreen, SettingsScreen, MembershipScreen, SplashScreen）。
- lib/providers/：状态管理（PlantProvider 管理植物数据；SettingsProvider 管理主题/设置/本地化开关等）。
- lib/services/：ApiService（网络/外部 API 抽象）、LocationService/WeatherService（位置与天气获取逻辑）等。
- lib/models/：数据模型（Plant、用户设置等），配合 json_serializable 生成序列化代码。
- lib/themes/：AppThemes 定义不同主题（动态/静态），并对 Windows 做字体调整。
- lib/widgets/：自定义 UI 组件和动画（如 GlassBottomNavigationBar、apple 风格组件）。
- assets/：图片、示例数据、启动图片等（nina.png、windows_icon.png、植物图片等）。
- windows/：Windows 平台构建文件，包含 runner 与 CMake 配置。
- 项目规划/：含设计草图、需求说明与待办（已有文件），将新增本报告。

## 4. 主要依赖与用途（来自 pubspec.yaml）
- UI：flutter，cupertino_icons
- 状态管理：provider
- 网络：http, dio
- 本地存储：sqflite, shared_preferences, sqflite_common_ffi（桌面）
- 图片/视频处理：image_picker, cached_network_image, video_player
- 位置与权限：geolocator, permission_handler
- 国际化/本地化：flutter_localizations, intl
- 代码生成：json_annotation, json_serializable, build_runner
- 桌面窗口：window_manager
- 启动页：flutter_native_splash

## 5. 平台支持与特殊处理
- Windows：
  - 初始化 window_manager，设置窗口尺寸、最小/最大尺寸、图标与标题栏样式。
  - 使用 sqflite_common_ffi 并设置 databaseFactoryFfi 以在桌面上使用 SQLite。
- Android/iOS：标准 Flutter 构建流程，Android 有 gradle 配置与 keystore。

## 6. 数据存储与同步
- 本地：sqflite 存储结构（植物表、提醒表等，需查看 models / providers 获取 schema 细节）。
- 轻量缓存：shared_preferences 用于保存用户设置与简单标志。
- 同步：代码中存在 ApiService，推断用于向远程服务上载图片/数据或拉取识别与诊断结果。会员系统可能涉及认证与云端同步。

## 7. 本地化、主题与可访问性
- 支持中/英两种语言，使用 Flutter 的 localizations delegate。
- 主题支持：静态主题与动态主题（dynamic），并包含玻璃风导航栏等自定义样式。
- 建议进一步审查字体与色彩对比以保证无障碍可访问性。

## 8. 安全、隐私与许可注意点
- 许可：GPL，发布/分发须遵守 GPL 要求。
- 隐私：定位与相册权限涉及敏感数据（定位、图片）。需要加入隐私声明与授权理由，以及在移动平台的权限描述文件（AndroidManifest.xml / Info.plist）。
- 密钥与签名：android/app 下存在 upload-keystore.jks 与 key.properties，注意不要在公开仓库中泄露真实密钥。

## 13. 具体功能细节（逐项分解）

下面按模块拆解每个主要功能的预期行为、用户流程、数据模型与实现要点（以便开发与测试）。说明中有些为推断/建议，需结合代码或产品需求确认。

13.1 我的植物（Plant management）
- 主要能力：添加/编辑/删除植物条目；为每株植物保存图片、名称、品种、种植日期、位置、种植容器、标签（如 "室内/室外/多肉"）、养护计划与历史记录（浇水、施肥、换盆等）。
- 用户流程：
  - 新增：用户拍照或从相册选择图片 -> 输入名称/品种/标签 -> 选择养护模板或自定义提醒 -> 保存。
  - 查看：植物卡片显示缩略图、下次提醒时间、最近一次操作摘要；进入详情可查看完整历史与编辑。  
  - 操作历史：支持按日期追加养护记录（包括照片、备注、操作人、操作花费时间）。
- 数据模型建议（sqflite 表）：
  - plants: id, name, species, note, photo_path(s), created_at, updated_at, location, container, is_favorite
  - reminders: id, plant_id, type (watering/fertilize/other), schedule (cron-like or interval), next_due, enabled
  - care_logs: id, plant_id, action_type, timestamp, note, photos
  - photos: id, plant_id, path, uploaded(boolean), remote_url
- UI/UX 要点：植物列表支持筛选/搜索/分组（按标签、位置或状态），长按快速操作（标记已浇水、延迟提醒）。

13.2 养护提醒（Care reminders）
- 类型：定期提醒（间隔/固定日历）、条件触发（基于天气/土壤湿度/光照推断）、一次性任务。
- 触发机制：
  - 本地调度：使用平台本地通知引擎（flutter_local_notifications）在指定时间触发。  
  - 条件触发：通过 LocationService 获取经纬度 -> 调用天气接口（ApiService）获取降雨/湿度/温度 -> 根据植物设置规则调整提醒（例如雨天跳过浇水提醒）。
- 用户控制：可配置提醒音、是否重复、提醒提前量（例如提前 30 分钟）、打卡确认（确认操作后自动推下一次）。
- 数据表：reminders 已涵盖；另外建议保存通知历史表用于分析。
- 边界条件：处理时区变化、 DST、跨设备同步差异（若有云同步）。

13.3 拍照识别（Photo identify）
- 流程：拍照/选择图片 -> 预处理（压缩、裁剪、去元数据）-> 本地/云识别 -> 展示识别结果（名称、置信度、相似图片、养护建议）。
- 离线策略：若集成离线模型（体积大）则在本地返回优先结果；否则在离线时提示无法识别并允许保存图片以稍后上传。
- 返回数据：种类/属、置信度、常见问题、可参考资料链接、相似案例（社区/示例图）。
- UI：识别结果页提供一键保存为新植物、标记错误、分享结果与请求人工诊断入口。
- API 设计建议：POST /identify (multipart image) -> 返回 [{species, confidence, info_url, advice}]
- 隐私：上传前提示用户将图片上传到服务器并请求同意；在设置中允许关闭自动上传。

13.4 专业诊断（Professional diagnosis）
- 目标：在人为判断困难时提供专家建议或更复杂的病虫害诊断。
- 流程：用户提交一份诊断工单（植物ID/图片/描述/环境信息）-> 后端/第三方模型处理 -> 返回诊断结果与处置建议；对接人工客服时返回单号与预计响应时间。
- 支持：附带多张图片、采集时间、位置（可选）、历史养护记录以便提供上下文。
- 商业模式：该功能可作为会员增值或付费单次服务。

13.5 会员系统（Membership）
- 权限区分：免费/基础会员/高级会员等。高级功能示例：云端同步、批量识别、快速人工诊断通道、无广告、历史备份。
- 流程：在 MembershipScreen 展示套餐 -> 集成支付（Google Play、Apple、或第三方） -> 本地保存订阅状态并在服务器端验证（若使用云）。
- 数据：users, subscriptions 表（本地仅缓存验证结果）；对会员特权检查应在关键功能处作守护。

13.6 设置（Settings）
- 常见选项：主题选择（静态/动态/玻璃）、语言切换、中英文、通知偏好、隐私（图片上传/日志）、数据导入导出（JSON/SQLite 备份）、应用缓存清理。
- 高级：数据库迁移/导出、调试日志上传（用于用户反馈）。

13.7 数据同步与备份（若支持云）
- 模式：增量同步（基于时间戳或变更序列号），冲突解决优先本地或提供冲突合并界面。
- 接口举例：
  - POST /sync/uploadChanges
  - GET /sync/downloadChanges?since=timestamp
  - POST /media/upload
- 安全：API 使用 HTTPS；敏感数据加密；鉴权使用 token（OAuth2 或自签发 JWT）。

13.8 权限与隐私流程
- 权限申请顺序：先请求必要权限（相机/相册/位置）并在请求前弹窗解释用途；若拒绝，提供功能受限提示与设置跳转。  
- 隐私策略：明确说明图片用于识别/诊断与是否存储；提供图片删除接口与账户删除清理流程。

13.9 错误处理、重试与降级
- 网络：统一请求超时、重试策略（指数退避），对关键 API 返回友好错误信息（如 "网络错误，请稍后重试"）。
- 识别：识别失败时应提供重试、离线保存或人工提交选项。
- 数据库：读写异常时弹出提示并尝试自动恢复（或导出诊断日志让用户上报）。

13.10 测试要点（建议的测试用例）
- 单元测试：PlantProvider 增删改查、Reminder 计算下次触发时间逻辑、SettingsProvider 的持久化行为。
- 集成测试：拍照识别端到端（模拟 API 响应）、提醒触发（本地通知模拟或端到端测试工具）、数据库迁移场景。
- UI 测试：关键路径（新增植物、标记已浇水、识别并保存）、多语言切换验证。

13.11 性能与资源考量
- 图片处理：本地压缩与分辨率控制以降低上传流量；使用 cached_network_image 做网络图片缓存。
- 数据库：对 plants 表按常用查询列建立索引（例如 species、name）；对长期历史记录做分表或分页加载。
- 启动：异步加载不影响首屏渲染，延迟加载非必要服务（如定位或天气）。

13.12 可扩展功能（路线图建议）
- 社区/分享：用户可发布植物案例、提问与分享养护技巧，结合点赞/评论机制。  
- 模型本地化：集成更小的离线模型以提供即时识别体验（tradeoff: 安装包体积）。
- 智能推荐：基于历史数据与环境条件为用户生成个性化养护建议（如灌溉间隔预测）。
